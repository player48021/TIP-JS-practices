# Практическая работа №6
## Подключение браузерного приложения к HTTP API

**Студент:** Войнов Максимилиан Олегович  
**Группа:** ЭФБО-14-25  
**Вариант:** 1

### Цель
Подключить браузерный интерфейс к HTTP API, изучить `fetch`, JSON, HTTP-методы, CORS и обработку состояний загрузки/ошибок.

### Структура
- `api/` — учебный HTTP API с задачами и категориями;
- `src/api-client.js` — общий клиент HTTP-запросов;
- `src/main.js` — интерфейс, загрузка и изменение задач;
- `index.html`, `styles.css` — страница и стили;
- `checks/` — автоматические проверки API;
- `tools/serve.mjs` — статический сервер для браузера.

### Запуск
Нужен Node.js 18+.

В первом терминале из папки `practice-06`:
```bash
npm run start:api
```
Во втором терминале:
```bash
npm run start:web
```
Откройте `http://127.0.0.1:5506`. Проверки API запускаются командой `npm run check` (API должен быть запущен).

### Что проверить
1. Загрузить список и категории.
2. Отфильтровать задачи по статусу и строке поиска.
3. Создать задачу с корректными данными.
4. Попробовать отправить пустое название и убедиться, что сервер вернул ошибку.
5. Переключить статус и удалить задачу.
6. Остановить API и убедиться, что интерфейс показывает понятную ошибку.

### Вывод
Браузерный клиент не должен обращаться к внутренним данным сервера напрямую: он использует HTTP-контракт. `fetch` отклоняет Promise при сетевой ошибке, но не при статусах 4xx/5xx, поэтому проверяется `response.ok`. Сервер проверяет входные данные самостоятельно, а CORS разрешает запросы со страницы другого origin.

### Результаты
Автоматическая проверка `npm run check` выполнена: все проверки API пройдены. Ручные сценарии в браузере необходимо выполнить самостоятельно.
